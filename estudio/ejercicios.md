# Práctica de laboratorio, no retos reales

Estos ejercicios son preparación propia, no preguntas filtradas ni resultados de la plataforma. Usar laboratorio autorizado, no gastar intentos competitivos. La pareja revisa evidencia y formato. Si no hay entorno, realizar lectura guiada del material y anotar qué falta para practicar.

| ID | Práctica | Qué demuestra aprendizaje |
|---|---|---|
| LAB-M01 | Identificar tenant/suscripción/grupo/app/plan | Distingue objetos y muestra evidencia del alcance |
| LAB-M02 | Seguir una petición navegador→API | Localiza método, ruta, estado y capa de fallo |
| LAB-M03 | Contrastar cliente HTTP y navegador | Explica si hay evidencia de CORS y qué falta |
| LAB-M04 | Diagnosticar variable ausente en copia de laboratorio | Relaciona configuración con fallo y verifica corrección |
| LAB-M05 | Investigar HTTP 500 y dependencia | Distingue síntoma de causa con logs/traza |
| LAB-M06 | Leer pipeline fallido | Identifica primera falla relevante, entrada y etapa |
| LAB-M07 | Leer diff y versión desplegada | Explica por qué rama actual no prueba versión de nube |
| LAB-M08 | Leer plan Terraform | Distingue cambios propuestos y riesgo de eliminación |
| LAB-M09 | Adaptar KQL entre scopes | Valida tabla/campos/tipos y consulta sin inventar resultado |
| LAB-M10 | Muestra vs conteo | Demuestra que take/limit no determina total |
| LAB-D01 | Ubicar entidad/ID e intervalo | Conserva nombre e ID exactos con contexto |
| LAB-D02 | Seguir transacción y dependencia | Identifica dónde ocurre la observación y qué la explica |
| LAB-D03 | Consultar logs con DQL | Filtro/ventana correctos y campos reales |
| LAB-D04 | Relacionar servicio y host/proceso | Evita confundir una instancia con el servicio completo |
| LAB-D05 | Analizar Kubernetes si está disponible | Distingue namespace/workload/pod y relaciones |
| LAB-D06 | Analizar un problema y causa propuesta | Contrasta correlación con evidencia pertinente |
| LAB-D07 | Investigar acción/sesión de usuario | Separa frontend/backend y Synthetic/RUM |
| LAB-D08 | Consultar un evento de negocio disponible | Define evento, ventana y unidad sin extrapolar tráfico |
| LAB-E01 | Simular candidata ambigua con un intento | Revisor identifica unidad/ID/ventana antes de enviar |
| LAB-E02 | Simular respuesta incorrecta | Conserva feedback y cambia hipótesis con evidencia nueva |
| LAB-E03 | Simular feedback pendiente y luego confirmado | Mantiene un envio_id y dos eventos, no dos intentos |
| LAB-E04 | Dos preguntas en ramas distintas | Sincroniza registros sin borrar aportaciones ni force-push |

No guardar simulaciones dentro de carpetas de retos reales. Registrar práctica en estudio/progreso.md y evidencias de laboratorio claramente identificadas. No cargar cuatro personas leyendo todo el temario en serie: cada pareja practica su foco y revisa resultados del otro.
